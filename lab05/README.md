### Задание 4 **(2)**

*Рассмотрим следующий пример в IDLE Python*
```
>>> x = 99.99
>>> int(x/10+0.001)
9
```
*Результат должен был быть равен 10, однако оказался другим. Почему так произошло?
Как исправить программу, чтобы она корректно переводила вещественные числа в целые?*

Число 99.99 в двоичном виде хранится с погрешностью. При делении на 10 получается число чуть меньше 9.999 (например, 9.998999...). 
Добавление 0.001 не компенсирует эту погрешность, результат все еще меньше 10. Функция int() просто отбрасывает дробную часть, 
поэтому получается 9, а не 10.


Чтобы исправить, нужно использовать округление вместо отбрасывания.
### Задание 5. **(2)**

*Рассмотрите следующую программу. Объясните результаты ее работы. В частности,
как величина* $y$ *повлияла на ответ?*
```
x = 1/3
y = 1
for i in range(20):
    print((x+y)-y)
    y*=10
```
*В отчете требуется привести вычисления для оценки погрешности.*

Программа выводит (x+y)-y, где x = 1/3, а y последовательно умножается на 10 (1, 10, 100, ...).
Пока y маленькое (до 10^15), результат близок к 0.333.
Когда y становится очень большим (например, 10^16), мантисса типа double (52 бита) не может одновременно хранить и большую целую часть y, 
и маленькую дробную часть x. 
Число x теряется при сложении (происходит округление x+y до y). В итоге (x+y)-y дает ровно 0.0.
Оценка погрешности: погрешность x составляет примерно 2^-54. 
При добавлении к y=10^k абсолютная погрешность суммы становится 10^k * 2^-52. 
Когда это значение превышает x, x полностью теряется.


### Задание 6 **(2)**

*Для какого минимального значения* $n$ *программа на С++ выведет* **inf**? *Объясните
ответ.* *Что произойдет, если тип* **double** *заменить на* **long double**?
```
int n=...;
double s = pow(2, n);
std::cout << std::fixed << s << std::endl;
```

Минимальное n для inf в double:
Стандарт IEEE 754 для double имеет 11 бит под порядок. Максимальный порядок 2^10 - 1 = 1023. Максимальное число примерно 2^1024.
При n = 1024 функция pow(2, 1024) вернет inf.

Если заменить на long double:
В большинстве реализаций long double имеет 15 бит под порядок. Максимальный порядок 2^14 - 1 = 16383.
inf появится при n = 16384.

### Задание 8 **(2)**

*Какое минимальное натуральное число при преобразовании в тип* **double** *записывается с погрешностью? Объясните
ответ. Почему следующее за ним число уже выводится без погрешности?*

минимальное натуральное число, которое при преобразовании в double записывается с погрешностью:
9007199254740993 (это 2^53 + 1).

Тип double имеет 52 бита мантиссы плюс 1 неявный бит, итого 53 бита точности. 
Он может точно представлять все целые числа до 2^53. Число 2^53 + 1 требует 54 бита, 
поэтому оно округляется до ближайшего четного числа 2^53.

Следующее число 2^53 + 2 является четным, для его представления достаточно 53 бита мантиссы, поэтому оно записывается точно.
